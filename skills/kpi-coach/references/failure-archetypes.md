# Failure archetypes — fast catches for REVIEW mode

When a founder names an existing KPI, most fall into one of these patterns. Name the archetype and the gate it fails, then coach toward the value event underneath.

| Archetype | Examples | Fails gate |
|---|---|---|
| **Vanity total** (cumulative, only goes up) | total signups, total downloads, registered users | 4, 5 |
| **Activity / plumbing** (motion, not value) | logins, sessions, DAU without a value event, page views | 1 |
| **Lagging financial** | MRR, revenue, LTV, GMV, ARPU, bookings | 3 |
| **Acquisition-bound** (needs new logos to grow) | total users, MoM user growth, new signups/week | 4 |
| **Correlate-not-cause** proxy | "users who did X retain better" (X is a symptom, not a lever) | 2 (empirical) |
| **Gameable throughput** (a target, not a unit) | calls made, tickets closed, meetings booked, features shipped | 5 |
| **Percentage headline** (differenced week over week) | conversion %, trial-to-paid %, MoM % as the number you track | 9 |

## How to redirect each

- **Vanity total → flow of a value event.** "Total signups" → "weekly active accounts that hit [value action]."
- **Activity → value-exchange.** Ask what the customer is *getting* when they log in; measure that moment instead.
- **Lagging financial → its leading driver.** Revenue is the outcome; find the value event that precedes and predicts it.
- **Acquisition-bound → within-customer depth.** Move from "how many customers" to "how much value each active customer gets."
- **Correlate-not-cause → run the experiment.** Keep it as a leading indicator, but don't call it a driver until driving it up improves retention (see `retention-proof.md`).
- **Gameable throughput → the customer-value it's a proxy for.** "Meetings booked" matters only if it maps to a customer outcome; measure the outcome.
- **Percentage headline → the underlying count.** Track the numerator as a count; keep the rate as a derived diagnostic (see `kpi-vs-okr.md`).

A KPI can be a fine *diagnostic* and still fail as a *primary* KPI — the point of REVIEW is to make sure the **one primary** metric is a validated value driver, and to relegate the rest to the secondary/health tier.
